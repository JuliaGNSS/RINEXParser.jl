# Contributing

Use four-space indentation, descriptive `snake_case` function names, and
`UpperCamelCase` type names. Prefer multiple dispatch for extension points.
Keep file-format units and time conventions explicit in public docstrings.

## Checks

Run the test suite, including Aqua:

```sh
julia --project -e 'using Pkg; Pkg.test()'
```

Tests are grouped by feature in `test/`; shared fixtures live in `helpers.jl`.

CI uses JuliaFormatter 2.8.5 with `.JuliaFormatter.toml`. Install that exact
version in a separate environment and format the same paths as CI:

```sh
julia --project=/tmp/rinex-formatter -e 'using Pkg; Pkg.add(PackageSpec(name="JuliaFormatter", version="2.8.5"))'
julia --project=/tmp/rinex-formatter -e 'using JuliaFormatter; format(["src", "test", "docs/make.jl"])'
```

Build the documentation locally; examples execute during the build and
undocumented exports or unresolved references fail the build:

```sh
julia --project=docs -e 'using Pkg; Pkg.develop(PackageSpec(path=pwd())); Pkg.instantiate()'
julia --project=docs docs/make.jl
```

## Commits and releases

Use Conventional Commits, such as `fix(obs): validate epoch fields` or
`feat(nav): support another record type`. Releases, version updates, and the
changelog are generated by semantic-release; do not edit release artifacts
manually.

For a change that breaks the latest released API, use `!` in the subject and a
`BREAKING CHANGE:` footer explaining the change and migration. Changes to API
introduced within the same unreleased branch do not require a breaking marker.
